# Персональні дані учнів

Чернетка для вчителя (SPEC 14). Опис нижче відповідає тому, як зроблено код (Фаза 2); текст повідомлення — редагує вчитель.

## Що зберігаємо

| Дані | Навіщо | Де в базі |
|---|---|---|
| Прізвище та ініціал імені (`Коваль О.`) | вчитель бачить, хто виконав завдання | `students.last_name`, `first_initial` |
| Клас і номер у списку | розподіл ДЗ, логін | `students.class_id`, `number` |
| Логін (`8b-07`) | вхід | `students.login`, Supabase Auth |
| Пароль | вхід | **лише хеш** у Supabase Auth; у відкритому вигляді вчитель бачить його один раз — одразу після створення, на картці входу |
| Позначка «спрощений режим» | інший вигляд уроку | `students.simplified_mode` — технічний прапорець, без причини |
| Час останнього входу | вчитель бачить, хто вже увійшов | `students.last_login_at` |
| Результати ДЗ і квізів (з Фази 4) | оцінювання | `submissions`, `quiz_answers` |

**Не зберігаємо:** ім'я повністю, по батькові (відкидається під час імпорту), дату народження, телефон, email, адресу, фото, діагнози. Акаунт учня має технічну адресу `<логін>@students.invalid` — це не пошта, листи на неї не надсилаються.

Журнал дій вчителя (`audit_log`): створення акаунтів, нові паролі, архів — без паролів.

## Де і хто має доступ
- Supabase (Postgres), **регіон ЄС**. Сайт — Cloudflare (статичні файли, без даних учнів).
- Доступ до даних класу — лише вчитель цього класу; учень бачить лише себе (Row Level Security, автоматичні тести).
- Без реклами, трекерів і сторонньої аналітики.
- Бекапи — щотижня, зашифровані ключем, який є лише у вчителя (`docs/setup.md`, розділ 7.3).

## Скільки зберігаємо
- Учень, що вибув, — «Архів»: вхід вимкнено, результати зберігаються до кінця навчального року.
- Наприкінці року — «Закрити рік» (SPEC 14): експорт результатів для вчителя, видалення акаунтів учнів. *(з'явиться пізніше; до того — вручну з погодженням вчителя)*
- Артефакти бекапів у GitHub видаляються автоматично через 90 днів.
