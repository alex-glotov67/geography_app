# CLAUDE.md — правила роботи в репозиторії «Географія 6–9»

Повне технічне завдання — `SPEC.md` (версія 2.3.2). Макети — `docs/design/`. Прочитай його на початку кожної сесії.

## Контекст (коротко)
- Інтерактивний ресурс уроків географії для 6–9 класів НУШ, навчальний рік 2026–2027, заклад загальної середньої освіти України.
- Є уроки й тренування (без входу), акаунти вчителя й учнів, ДЗ з серверною перевіркою, кабінет вчителя, живий квіз на уроці.
- Користувачі: учні (часто старі Android, слабкий інтернет), вчитель (ПК і проєктор).
- Стек: React + Vite + TypeScript, TanStack Router/Query/Table, Zustand, React Hook Form + zod, Mantine, dnd-kit, vite-plugin-pwa; Supabase (Postgres, Auth, RLS, Realtime, Edge Functions на Deno), регіон ЄС; локальний Supabase CLI для розробки і CI, один хмарний prod-проєкт; хостинг — Cloudflare Pages; CI — GitHub Actions.
- Навчальна база: модельна програма НУШ «Географія. 6–9 класи» (наказ МОН №795 від 12.07.2021), підручники Гільберг Т., Довгань А., Совенко В., робочі зошити «Генеза», КТП вчителя.
- Пілот: 8 клас. Дизайн затверджено на полотні; скриншоти — `docs/design/`, токени — розділ 13 SPEC.

## Як працюємо
- Виконуй **лише ту фазу**, яку назвав вчитель (розділ 16 SPEC). Не переходь до наступної самостійно.
- З Фази 1 кожна фаза — окрема гілка `phase-N-<коротко>` і PR у `main`; у `main` напряму не комітимо. Зливає вчитель після зеленого CI.
- Перед кодом — короткий план файлів і змін. Наприкінці — звіт: зроблено / перевірено (розділ 15) / `TODO(teacher)` / відкриті питання.
- Власник — вчитель і React-розробник (React, Vite, Zustand, React Hook Form, TanStack Query; бекенд раніше на Node/Express). Говори технічно. Нове для нього — Supabase, Edge Functions (Deno), zod (знає yup), Mantine: коротко пояснюй при першій появі.
- Налаштування сервісів — покроково в `docs/setup.md`.

## Зміст
- **Не вигадуй навчальний зміст** (теми, §, години, результати, номенклатуру, практичні, критерії). Лише з `sources/` або від вчителя; інакше — `TODO(teacher): …`.
- **Не вигадуй статистику:** кожне число з `source` і `asOf`.
- **Не копіюй тексти підручників і сторінки зошитів** у сайт; завдання формулюй сам.
- **Кордони України** на картах — міжнародно визнані (включно з АР Крим і м. Севастополь); джерело й ліцензія — у `docs/maps.md`.
- Відео — лише українською і лише з `videos.approved = true` (позначає вчитель, не агент).
- Мова — українська; до учня — на «ти».
- `status: published` — лише з `reviewed_by_teacher = true` і без `TODO(teacher)`; публікує вчитель.
- Адреса уроку — стабільний `slug` (`/lesson/<slug>`), не `id`: він друкується в QR і переноситься в пакетах.

## Безпека і дані
- **Секрети** (service role key тощо) — ніколи в клієнтському коді і в git; лише `.env.local` і секрети Edge Functions.
- **RLS на кожній таблиці**, з автоматичними тестами. Учень бачить лише своє; вчитель — лише свої класи.
- **Ключі `secure`-завдань (ДЗ, квіз) недоступні клієнту** — ні в `dist/`, ні через view, Storage чи кеш PWA; бали рахує сервер. CI і RLS-тести це перевіряють.
- **Зміст `secure`-завдань** бачать лише власник і учень з призначенням (`opens_at <= now()`); учасники квізу не читають `tasks` — поточне питання без ключа йде через `quiz_sessions.current_question` (`quiz_advance()`); гість у блоці ДЗ бачить лише кількість завдань.
- Персональні дані учнів — лише прізвище, ініціал, клас, логін, результати. Паролі — тільки через Supabase Auth; у відкритому вигляді вчитель бачить їх один раз.
- Без трекерів, сторонньої аналітики, реклами.
- Зміни БД — лише міграціями в `supabase/migrations/`.

## Код
- Стек — розділ 3 SPEC. Не додавай бібліотек, що дублюють обрані: без axios (є `supabase-js`), Redux (є Zustand), Formik/yup (є RHF + zod), інших UI-бібліотек (є Mantine).
- Серверний стан — TanStack Query поверх `supabase-js`; клієнтський — Zustand.
- Окремого бекенд-сервера немає. Серверна логіка — лише Edge Functions `manage-students`, `submit-homework`, `quiz-answer` + SQL view/функції. Нова функція — тільки з погодженням.
- Перевірка завдань — один модуль `supabase/functions/_shared/scoring` (чистий TS), спільний для клієнта і сервера; покривай тестами.
- zod-схеми — єдине джерело типів змісту і payload-ів (`z.infer`).
- Типи БД — генеруй `supabase gen types`, не пиши вручну.
- Mantine налаштовується через тему (`theme.components`, CSS-модулі) під макети `docs/design/`; стандартний вигляд Mantine — не еталон.
- Шрифти — з пакетів `@fontsource` у бандлі (`src/theme/fonts.css`), карти — локально; без зовнішніх CDN.
- Дизайн — за розділом 13 SPEC і макетами; без декоративних тіней, градієнтів, емодзі; цілі дотику ≥ 44 px.
- Міграції й функції — спершу локальний Supabase і CI, prod — лише вручну після перевірки.
- Маршрути — history-режим (`/lesson/...`), без `#`.
- RLS-політики явно виключають анонімних користувачів (`is_anonymous`), окрім участі в квізі. Запис у `quiz_answers` і `submissions` — лише через Edge Functions.
- Зміст (уроки, завдання, квізи, медіа) живе в Postgres і Supabase Storage і редагується в конструкторі вчителя (розділ 10 SPEC). Справжніх уроків у репозиторії немає — лише демо-пакети `seed/` з позначкою «ДЕМО».
- Завдання `open` (тренування) — ключ доступний клієнту; `secure` (ДЗ, квіз) — ключ лише в Edge Functions. Не змішувати; `open → secure` для опублікованого — лише через копію.
- `short_text` — лише `secure`. Цілі дотику ≥ 44 px скрізь, включно з конструктором. Логіни й паролі — JetBrains Mono (латиниця, одна вага): таблиця учнів, картки входу, поле «Логін» на екрані входу.
- Основні таблиці мають `school_id` (підготовка до кількох вчителів); унікальність `slug` — у межах вчителя.
- Новий тип завдання чи блоку — повний модуль: рендер, редактор, шаблон, друк, zod-схема, перевірка з тестами; він має автоматично з'явитися в конструкторі, банку, друці й імпорті.
- Формат пакета `.geo.zip` версіонується; змінив схему — додай міграцію старих пакетів і round-trip тест.
- Після змін у змісті чи схемах — `npm run validate`. Кожна нова можливість — з оновленням `README.md`.

## Не роби без явного дозволу вчителя
- Видаляти чи перейменовувати зміст (уроки, завдання, квізи, медіа, демо-пакети `seed/`), видаляти дані учнів або акаунти. Автоматичне прибирання анонімних акаунтів гостей квізу (6.2 SPEC) — частина специфікації, не виняток.
- Змінювати політики RLS, міграції попередніх фаз, ключі й налаштування Supabase; деплоїти на prod.
- Публікувати уроки (`status: published`).
- Додавати платні сервіси чи сервіси, що вимагають від учнів email або телефон.
